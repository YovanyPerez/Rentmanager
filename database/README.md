# Database

MySQL 8.4 schema for RentManager. `01_schema.sql` is the **source of truth** for the schema; JPA/Hibernate runs with `ddl-auto=validate` (no automatic schema changes).

## Tables

```text
users                    roles ADMIN / OWNER / TENANT (single enum column, no roles table)
owners                   optional 1:1 link to users (user_id nullable)
tenants                  optional 1:1 link to users (user_id nullable)
properties               belongs to an owner
property_images          belongs to a property; uploaded files, position 0 is the cover
contracts                belongs to a property and a tenant
payments                 belongs to a contract
maintenance_requests     belongs to a property; created_by references a user
```

## Decisions

- **No `roles` table**: there are exactly three fixed roles, so `users.role` is a checked `VARCHAR` (`CHECK (role IN (...))`). Simpler and sufficient; revisit only if roles become dynamic.
- **Status/role columns use `VARCHAR` + `CHECK`** instead of MySQL `ENUM` so Hibernate's `validate` mode accepts them (MySQL reports `ENUM` as `CHAR`). The allowed values are still enforced by the database.
- **Owners and tenants are business entities**, not users. They can exist without login (`user_id` NULL) and be linked to an account later. `user_id` is unique when set.
- **One ACTIVE contract per property** is enforced at database level: `contracts.active_property_id` is a stored generated column (`property_id` when status is `ACTIVE`, else NULL) with a unique index. MySQL allows multiple NULLs, so any number of non-active contracts can exist.
- **One payment per contract and due date** (`uq_payments_contract_due`), which also prevents duplicate monthly instalments.
- **No DELETE for payments** in the API: financial records change status (`CANCELLED`), they are never deleted.
- **Contract rent is copied** from the property into `contracts.monthly_rent` so price changes do not alter historical contracts. The same applies to `currency`: contracts copy the property currency when created, and payments inherit it.
- **Currency is per property** (`properties.currency`, ISO 4217 restricted to COP/EUR/MXN/USD by `chk_properties_currency`). There is no foreign-exchange conversion anywhere: the dashboard totals income per currency.
- **Property images are files, not blobs**: `property_images` stores the stored file name, content type and position; the bytes live on the backend disk (`UPLOADS_DIR`, default `backend/uploads`, served at `/uploads/**`). Deleting a property cascades its image rows; the API deletes the files when an image is removed.
- **Seed data contains no users**: the admin account is created in Phase 5 with a BCrypt hash generated by the backend. Never store plain-text passwords.

## Usage

```bash
cp .env.example .env
docker compose up -d          # applies 01_schema.sql and 02_seed.sql on first run
docker compose down           # stop (data is kept in the mysql_data volume)
docker compose down -v        # stop and wipe (schema/seed re-applied on next up)
```

The init scripts only run when the data volume is empty. After changing the schema, reset with `docker compose down -v && docker compose up -d`.

Connect:

```bash
docker exec -it rentmanager-mysql mysql -urentmanager -p rentmanager
```
